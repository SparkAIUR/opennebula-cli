# Command Model

## Canonical syntax

The preferred CLI grammar is:

```bash
one [GLOBAL OPTIONS] <resource> <verb> [RESOURCE ARGS] [RESOURCE OPTIONS]
```

Examples:

```bash
one vm list
one --output json vm list
one --profile prod template show 24
one --no-pager host flush 0
one workflow template render workflow.yaml --vars-file vars.yaml
one workflow vm apply bulk-init.yaml --wait-ready
```

## Compatibility syntax

Compatibility wrappers keep the captured official family names available:

```bash
one<resource> [GLOBAL OPTIONS] <verb> [RESOURCE ARGS] [RESOURCE OPTIONS]
```

Examples:

```bash
onevm list
onevm --output json list
oneimage --profile prod show 13
onecluster --output yaml show 0
```

## Coverage

The CLI ships complete, independent command profiles for OpenNebula 7.0 and 7.4. The static help tree is their union; authenticated capability checks reject commands unavailable on the selected server line before the operation call.

- `vm`
- `host`
- `image`
- `template`
- `vnet`
- `datastore`
- `cluster`
- `flow-template` (compatible `oneflow-template` wrapper)
- `form`, `provider`, `provider-template`, `provision`, and `provision-template` on 7.4

Typed commands such as `list`, `show`, `template instantiate`, recovery helpers, and selected VM lifecycle operations return normalized SDK models. The broader official surface is routed through a generic service runner that preserves command availability and core XML-RPC behavior while deeper typed models are added incrementally.

## Global options vs resource options

Global options are handled by the root application:

- `--profile`
- `--context`
- `--require-context`
- `--backend`
- `--endpoint`
- `--auth`
- `--user`
- `--password`
- `--password-stdin`
- `--output`
- `--no-pager`
- `--timeout`
- `--no-verify`
- `--cert-dir`
- `--verbose`
- `--debug`
- `--compact`, `--value`, `--select`, `--filter`, `--sort`, `--no-header`
- `--full`, `--official-schema`

Prefer placing them before the resource verb.

This is required for most commands. Selected commands may provide local convenience overrides. For example, `one vm show 42 --output json` is supported.

Resource options stay on the subcommand itself:

```bash
one vm poweroff 42 --wait --timeout 600 --no-progress
one --output json vm disk-list 42
one --output json vm recover 42 --retry
one --output json image owner 18
one template instantiate 24 --name build-vm
one workflow vm init bulk-init.yaml --vm-name alice --set global.resources.ram=8Gi
one agents
```

## Output modes

Supported output modes:

- `table`
- `json`
- `jsonl`
- `yaml`
- `xml`
- `csv`
- `raw`

Guidance:

- use `table` for interactive operator sessions
- use `json`, `yaml`, `csv`, or `raw` for automation
- use `jsonl` for streaming one object per line
- prefer `--output` at the root position for consistency

The views are distinct contracts:

- default: stable normalized typed model
- `--full`: lossless normalized backend payload
- `--official-schema`: upstream key names and nesting; XML repeats upstream vector element names

## Wait behavior

Waiter-enabled lifecycle paths:

- `vm poweroff --wait`
- `vm poweroff-hard --wait`
- `vm wait`
- `workflow vm init --wait-ready`
- `workflow vm apply --wait-ready`

Example:

```bash
one --output json vm poweroff 42 --wait --timeout 600 --no-progress
one --output json vm wait 42 --state ACTIVE --lcm-state RUNNING --timeout 10m
one workflow vm apply bulk-init.yaml --wait-ready --timeout 600 --poll-interval 2
```

## Validation boundary

Static and local checks:

```bash
uv run python tools/check_command_coverage.py
uv run python tools/check_catalog_schema.py
uv run pytest
```

Authenticated read-only validation for named contexts is implemented by `tools/validate_readonly_context.py`. Mutation validation remains a separate gate and must use a suitable disposable environment with `e2e-*` resources; never infer mutation safety from read-only success.
