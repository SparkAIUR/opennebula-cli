# Parity Roadmap

The command parity program uses independently materialized profiles in `src/opennebula_cli/catalogs/profiles/`. Legacy family catalogs remain under `src/opennebula_cli/catalogs/v7_0/base/` while they are migrated to the richer schema.

## OpenNebula 7.0 and 7.4 coverage

The shipped profiles are the CI source of truth and do not depend on private `refs/*` files. Coverage includes all existing official families plus these 7.4 deltas:

- `onevm`
- `onehost`
- `oneimage`
- `onetemplate`
- `onevnet`
- `onedatastore`
- `onecluster`
- `oneflow-template`
- `oneform`, `oneprovider`, `oneprovider-template`, `oneprovision`, `oneprovision-template`
- VM exec and VM-group operations
- cluster plan operations, group VLAN rules, and OneFlow schedule deletion

The first full-coverage pass provides command availability, required arguments, and core/high-value options through the service layer. Commands that already have typed SDK paths keep those typed implementations. The broader official parity surface uses a generic XML-RPC-shaped runner so each captured verb is available in canonical form and through the compatibility wrappers.

Validation status:

- both shipped command profiles match the static Typer command union
- 7.4 DR read-only checks pass on PyONE and raw backends
- 7.0 dual-backend local protocol compatibility passes
- guarded preview wrappers remain unavailable unless explicitly enabled because stock 7.4 routes are absent

## Project helpers

Additional helper commands remain intentionally outside the official capture:

- `vm disk-list`
- `vm wait`
- `vm poweroff-hard`
- `vm reboot-hard`
- `image owner`
- `raw call`
- `agents`
- `workflow ...`

## Remaining roadmap

Future work should deepen typed models for the broad official compatibility runner, validate OneForm against a configured disposable server, and add live mutation evidence for the new 7.4 operations.

## Release policy

Public package versions mirror the targeted OpenNebula compatibility line.

- current release: `7.4.0`
- compatibility targets: OpenNebula `7.4.x` and retained `7.0.x`
