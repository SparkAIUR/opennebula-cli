# Parity Roadmap

The command parity program is organized in waves and tracked in YAML catalogs under `src/opennebula_cli/catalogs/v7_0/base/`.

## Wave 1

- `onevm`
- `onehost`
- `oneimage`
- `onetemplate`

Implemented commands:

- `vm`: `list`, `show`, `poweroff`
- `host`: `list`, `show`, `flush`
- `image`: `list`, `show`, `delete`
- `template`: `list`, `show`, `delete`, `instantiate`

Validation status:

- read-only `list` and `show` are live-validated
- `template instantiate` and `vm poweroff` are live-validated on disposable fixtures
- `host flush`, `image delete`, and `template delete` remain implemented but not yet required as live release blockers

## Wave 2

- `onevnet`
- `onedatastore`
- `onecluster`

Current status:

- `list` and `show` are implemented
- read-only `list` and `show` are live-validated
- mutating Wave 2 verbs remain cataloged, not implemented

## Wave 3

## Plugin wave

Planned extensions:

- OneFlow plugin boundary
- plugin diagnostics
- entry-point based registration

## Workflow automation track (`7.0.1`)

Implemented:

- `workflow template init`
- `workflow template render`
- `workflow template import`
- `workflow template apply`
- `workflow vm init`
- `workflow vm apply`

Capabilities:

- Jinja-driven VM template rendering with cloud-init support
- local file inclusion helpers (`read_file`, `read_file_b64`)
- remote text fetch helper (`fetch_url`) with method/headers/params/body/timeout controls
- single and bulk VM initialization with per-entry status reporting and partial-failure resilience

## Release policy

Public package versions mirror the targeted OpenNebula compatibility line.

- current release: `7.0.1`
- compatibility target: OpenNebula `7.0.x`
- historical bootstrap release: `0.1.0`
